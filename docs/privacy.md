# GoreeCloud Social — Privacy Status

## Current data boundary

The foundation models only Social-owned profile metadata, social relationships, content metadata, media storage references, reactions/reposts, memberships, and reports. It does not ingest contacts, location, advertising identifiers, behavioral recommendation histories, third-party analytics, or external tracking data.

`identity_subject` is an external identity reference. GoreeCloud Social does not implement a second password or authentication store.

## Privacy Shield work required

Before broader functionality is enabled, the application must define and enforce:

- data categories and purposes;
- profile and post audience rules;
- contact-discovery consent and minimization;
- recommendation-signal collection and user controls;
- location and media-metadata handling;
- analytics boundaries;
- retention and deletion behavior;
- export and portability behavior;
- cross-application sharing/disclosure rules;
- moderator access and evidence retention;
- local-versus-remote processing transparency.

Privacy-sensitive functionality remains blocked until substantive Privacy Shield integration and acceptance exist.
